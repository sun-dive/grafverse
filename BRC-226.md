# BRC-226 — The Self-Running Counter

*An immortal, ownerless program on Bitcoin SV — the smallest working BRC-226 covenant.*

> **License:** Open BSV License Version 6 (© BSV Association). Every file in this reference carries that
> header. It is a **seed, not a spec** — take the block, change the rule, plant your own.

A **LiveCounter** is a single on-chain number that **anyone can push forward, one transaction per tick,
with no operator** — and that **no one can ever stop, censor, or destroy.** It is a self-replicating
("quine") covenant that carries its own counter in its own script and can only ever spend itself into a
copy of itself with `n → n+1`. There is no owner and no burn: the counter is immortal by design.

## How a tick works

Spending the counter is **permissionless** (no signature — the covenant is satisfied by transaction
introspection, not a key). The covenant reads the spending transaction's own sighash preimage via the
optimal **OP_PUSH_TX** primitive, reads `hashOutputs`, and forces the first three outputs to be exactly:

| output | rule | meaning |
|--------|------|---------|
| **out0** | the covenant re-created — same script, but `n → n+1` and `lastFunder → newFunder` | the tick (the quine) |
| **out1** | `DEPOSIT` sats → P2PKH(old `lastFunder`) | the relay refund |
| **out2** | `MARKFEE` (1 sat) → P2PKH(author) | a self-monetizing crumb |
| out3+ | signer-supplied: `OP_RETURN(mark)` + change | the wall (≤ 111-byte mark, any language) |

`HASH256(out0‖out1‖out2‖out3‖…) == hashOutputs` pins it. So `n` can **only** ever become `n+1`, the previous
funder is **always** repaid, and the crumb **always** reaches the author — the identity of the signer and the
text of the mark are the only free choices, and neither can bend the counter's path. **You can't fork a proof.**

Scope is `SIGHASH_ANYONECANPAY | ALL | FORKID` (`0xc1`), so any funder may add their own input to cover the
deposit + crumb + fee without invalidating the spend.

### Funding is self-moderating

A poster locks nothing: the deposit **circulates** (the next poster hands it straight back), the crumb is a
single satoshi, and the mark is a 0-value `OP_RETURN`. Because every post costs *some* real sats, spam prices
itself out — **no rate limits, no accounts, no moderators.** See the blueprint for the three funding models
(battery · shared pool · relay).

## Build & test

From `mint/` (Node 20+, esbuild + `@bsv/sdk` already vendored):

```sh
# structural: the covenant assembles, state is fixed-width
node -e "import('esbuild').then(e=>e.build({entryPoints:['test/lc.ts'],bundle:true,format:'esm',platform:'node',target:'esnext',outfile:'test/lc.mjs'}))" && node test/lc.mjs

# the money-proof: mint → tick → tick through the @bsv/sdk Spend interpreter, + tampered spends rejected
node -e "import('esbuild').then(e=>e.build({entryPoints:['test/lc-spend.ts'],bundle:true,format:'esm',platform:'node',target:'esnext',outfile:'test/lc-spend.mjs'}))" && node test/lc-spend.mjs   # 7/7

# end-to-end: real signed genesis + tick + tick, every input interpreter-valid
node -e "import('esbuild').then(e=>e.build({entryPoints:['test/lc-tx.ts'],bundle:true,format:'esm',platform:'node',target:'esnext',outfile:'test/lc-tx.mjs'}))" && node test/lc-tx.mjs   # 10/10
```

All three are green: the covenant is **674 bytes**, its state is fixed-width (so the quine stays byte-exact
every tick), a tick validates and chains, and tampering (wrong `n+1`, skipped repayment, altered crumb) is
rejected by the same script engine miners run.

## Deploy your own

See **`mint/tools/GO-LIVE.md`**. In short: fund a kept key, `--selftest` the tool (no key, no network),
dry-build, `--broadcast`, then point a `tip.php` at your genesis txid. The counter you mint is yours to
*start* — but, being ownerless and immortal, it belongs to no one thereafter.
